# Tracker Method Notes

## Research Position

Tracker experiments treat a 3D volume as a slice sequence. A tracker sample is typically a single `(volume, category)` sequence for categories such as RV, MYO, and LV.

The intended system is:

- image detector provides per-slice masks or high-confidence seeds
- tracker propagates/refines across neighboring slices
- merge/selection decides whether detector or tracker output is trusted

Current evidence does not support treating tracker-only output as the default final prediction.

## Strict Scribble Rule

For strict weak supervision:

- Tracker seed masks must come from scribble-trained detector predictions or documented pseudo-seed banks.
- Full labels are allowed for validation/test evaluation only.
- Full-supervised tracker checkpoints should not be used as the main weak-supervised method.

## Pseudo Seed Bank

Builder:

- `gq_scripts/preprocess/build_scribble_tracker_pseudo_seed_bank.py`

Joint seed scripts:

- `gq_scripts/preprocess/run_joint_tracker_pseudo_seed_banks.sh`
- `gq_scripts/preprocess/run_joint_tracker_pseudo_seed_banks_val_macro.sh`

The seed bank keeps high-confidence detector predictions that satisfy scribble consistency requirements.

## Training Components

Adapter:

- `sam3/model/sam3_tracker_train_adapter.py`

Loss:

- `sam3/train/loss/sam3_tracker_loss.py`

Weak tracker loss must preserve scribble `valid_mask` semantics and `ignore_index=255`.

V3 temporal losses:

- `temporal_ptr_weight`
- `temporal_area_weight`
- `temporal_centroid_weight`
- `temporal_min_area`
- `temporal_area_delta`
- `temporal_centroid_delta`

Current v3 evidence does not show a clear final Dice gain, so treat these losses as diagnostic/experimental.

## Inference Semantics

Main auto-seed inference:

- `gq_scripts/evaluate/tracker_auto_seed_inference.py`

Wrapper:

- `gq_scripts/evaluate/run_tracker_auto_seed_inference_and_eval.sh`

Important output distinction:

- `detector_predictions_segm.json` from tracker auto-seed inference is raw detector candidates inside the tracker workflow.
- It is not the official detector-only baseline.
- Fair merge should use official detector branch outputs generated by the detector-only pipeline.

## Evaluation

Final tracker judgment should use 3D Dice/IoU/HD95/NSD when available.

Do not select final medical conclusions only from 2D COCO AP.
